# Security Policy

## Supported content

This repository is an educational project under active development. Security fixes are applied to the latest version on the default branch; older examples are not maintained as separate releases.

## Reporting a vulnerability

Please do **not** open a public issue for a vulnerability that could put users, credentials, infrastructure, or data at risk.

Use GitHub’s private vulnerability reporting feature:

1. Open the repository’s **Security** tab.
2. Select **Advisories**.
3. Select **Report a vulnerability**.

Include:

- the affected file, component, or lab;
- the impact and realistic attack scenario;
- steps to reproduce or a minimal proof of concept;
- suggested remediation, if known.

You should receive an acknowledgement within seven days. Please allow time to validate and remediate the issue before public disclosure.

## Educational examples

Examples may intentionally trade production hardening for clarity or local reproducibility. Those trade-offs should be stated, but a documented limitation is not automatically a vulnerability.

Never use example credentials in a real environment. Never commit cloud keys, access tokens, kubeconfig files, private endpoints, or sensitive datasets.
